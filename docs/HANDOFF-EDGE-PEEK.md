# QuotaHalo 边缘窥视模式交接

## 分支与范围

- 开发分支：`codex/edge-peek`
- 基线分支：`main`（基线提交 `a4f02ee`）
- 当前版本：`0.4.6`
- 本分支只新增和修复极简模式下的边缘窥视功能，不改变完整模式的业务内容。

## 用户确认的最终要求

1. 软件启动时必须默认显示完整模式，不能记忆为启动即进入极简模式。
2. 边缘窥视只在极简模式启用；完整模式不参与自动吸附。
3. 极简窗口靠近显示器左侧、右侧或顶部时，自动进入边缘窥视；底部不吸附。
4. 在窗口靠近边缘的位置原地收起，不能自动移动到屏幕中央或固定位置。
5. 左右侧收起后显示 `20×60` 逻辑像素竖条；顶部显示 `135×20` 逻辑像素横条。
6. 边缘条展示 Codex 剩余 5 小时额度，内部进度条使用长条胶囊形状。
7. 边缘模式圆角为 5px；普通窗口仍使用原有圆角。
8. 鼠标悬停边缘条时展开为 `135×60` 极简窗口。
9. 鼠标离开整个展开窗口后，短延迟自动沿原来的边缘方向收起。
10. 按住边缘条拖动时，先展开再开始拖动；拖动结束后重新判断是否需要吸附。
11. 顶部展开和回缩时必须保持原来的横向位置；左右侧必须保持原来的纵向位置。
12. 展开后不得在极简模式与边缘模式之间反复闪动，也不得从顶部方向改判为右侧方向。

## 当前实现

### 原生窗口层

相关代码位于 `src-tauri/src/main.rs`。

- 吸附距离为 24 逻辑像素，并按当前 DPI 转换为物理像素。
- 使用 Tauri 提供的 Windows 显示器工作区计算左、右、上边缘；这可以兼容任务栏占用屏幕边缘的情况。
- 收起时直接调整原生窗口尺寸，不再依赖把大部分窗口移动到屏幕外：
  - 左/右：`20×60`
  - 顶部：`135×20`
- 展开时恢复为 `135×60`，并根据原吸附方向计算位置。
- `snap_edge_peek` 只负责首次检测方向；`collapse_edge_peek` 接收已确定方向，回缩时不会重新选择边缘。
- Windows 原生窗口区域会根据尺寸应用 5px 或普通窗口圆角。
- 下边缘没有加入方向候选，因此不会触发吸附。

### 前端状态

相关代码位于 `src/main.js`、`src/index.html` 和 `src/styles.css`。

- `edgePeekDirection` 保存当前吸附方向。
- `edgePeekExpanded` 区分收起与悬停展开状态。
- `edgePeekTransitioning` 防止移动、悬停和回缩命令并发执行。
- 展开后的自动回缩监听绑定在始终存在的 `.panel` 上，不再绑定会切换显隐的极简内容，避免 `mouseenter`/`mouseleave` 循环。
- 离开整个窗口 350ms 后才回缩；重新进入窗口会取消计时器。
- 边缘进度条复用 5 小时额度的剩余百分比和当前主题颜色，不发起额外额度请求。
- 页面启动时固定调用完整模式，不读取上次保存的极简状态作为启动状态。

## 已处理的问题

- 修复进入极简模式后只剩纯色、按钮和内容消失。
- 修复程序启动时错误进入极简模式。
- 修复只吸附但没有显示边缘窥视条。
- 修复左右侧不触发或依赖负坐标隐藏窗口的问题。
- 修复顶部吸附后被移动到固定居中位置。
- 修复顶部悬停展开后跳到屏幕右上角。
- 修复悬停时边缘模式与极简模式反复切换。
- 修复拖动边缘条时，窗口尚未展开就启动拖动的竞态。

## 真机验收清单

自动化测试不能代替原生窗口拖动，接手后应在用户实际 Windows 环境逐项确认：

1. 普通单显示器分别测试左、右、顶部吸附。
2. 顶部靠近左上角和右上角时，悬停后仍保持顶部方向。
3. 连续悬停、离开 10 次，确认没有闪动或来回切换。
4. 从三种边缘状态拖出窗口，确认先展开、可拖动并能再次吸附。
5. Windows 缩放为 125%/150% 时确认尺寸和位置正常。
6. 双显示器及任务栏位于左侧或右侧时确认使用正确工作区。
7. 确认底部边缘始终不吸附。
