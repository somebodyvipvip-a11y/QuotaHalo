# 托盘模式菜单与点击行为调整设计

## 背景

QuotaHalo 当前已经区分托盘单击和双击，但仍有两个交互缺口：左键单击会触发 Tauri 默认的托盘菜单展示；双击只处理从边缘模式恢复为完整模式，未覆盖普通极简模式。右键菜单也缺少直接切换完整、极简和边缘模式的入口。

本次调整统一托盘点击行为和模式转换规则，并确保所有显示和切换都基于窗口当前位置，不再把窗口重新放到桌面右下角。

## 目标

- 左键单击在当前位置隐藏或显示主窗口，不显示托盘菜单。
- 左键双击时，边缘模式和极简模式切换为完整模式；完整模式只显示并聚焦。
- 右键菜单增加完整模式、极简模式和边缘模式三个入口。
- 右键选择任一模式后，在当前位置完成切换、显示并聚焦窗口。
- 主动选择边缘模式时，自动吸附到当前显示器最近的左、右或上边缘。
- 后台额度刷新继续保持纯数据刷新，不改变窗口尺寸、位置或可见性。

## 非目标

- 不增加底部边缘模式，避免与 Windows 任务栏及工作区边界产生冲突。
- 不迁移现有全部模式状态到 Rust。
- 不改变程序首次启动时默认位于主显示器右下角的行为。
- 不移除右键菜单中的刷新、用量页面和退出功能。
- 不增加托盘菜单模式项的动态勾选状态。

## 方案选择

采用现有职责分工：前端维护显示模式和边缘会话状态，Rust 负责托盘事件、窗口显示、窗口尺寸以及屏幕坐标计算。

托盘菜单点击后由 Rust 向前端发送明确的模式请求。前端根据当前完整、极简或边缘状态选择对应转换，再调用 Rust 命令完成原生窗口尺寸和位置变更。只有原生操作成功后，前端才提交模式状态和持久化结果。

未采用以下方案：

- 把全部模式状态迁移到 Rust：状态会更集中，但会重复前端现有状态并扩大改动范围。
- 模拟现有界面按钮点击：实现简单，但隐藏窗口和边缘模式下容易发生 DOM 状态与原生窗口状态不同步。

## 托盘菜单

右键菜单按以下顺序显示：

1. 完整模式
2. 极简模式
3. 边缘模式
4. 分隔线
5. 刷新额度
6. 打开 ChatGPT 用量页面
7. 分隔线
8. 退出

三个模式项使用普通菜单项，不做动态勾选。选择模式后，窗口会在转换成功后显示并获得焦点。

Tauri 托盘配置显式关闭左键显示菜单。右键仍使用原生托盘菜单。

## 左键单击与双击

继续使用现有基于系统双击时间的判定机制：

- 第一次左键释放后延迟执行单击。
- 延迟结束前若收到双击事件，则取消该次单击。
- 单击在当前位置切换窗口可见性，不改变模式、尺寸和位置。
- 双击先确保窗口可见并获得焦点，再发送模式转换事件。

双击模式规则：

- 当前为边缘模式：沿当前边缘向屏幕内展开为完整模式。
- 当前为普通极简模式：在当前位置切换为完整模式。
- 当前为完整模式：不改变尺寸和位置，只显示并聚焦。

## 右键模式转换

### 完整模式

- 从边缘模式进入：沿当前边缘向屏幕内展开，并使用边缘会话保存的完整模式尺寸；若来源是极简模式，则使用默认完整模式尺寸。
- 从普通极简模式进入：以当前左上角为初始锚点切换为默认完整模式尺寸。
- 已是完整模式：不调整几何信息。
- 成功后清除边缘状态、持久化 `full`，显示并聚焦窗口。

### 极简模式

- 从边缘模式进入：沿当前边缘向屏幕内展开为默认极简尺寸。
- 从完整模式进入：以当前左上角为初始锚点缩小为默认极简尺寸。
- 已是极简模式：不调整几何信息。
- 成功后清除边缘状态、持久化 `compact`，显示并聚焦窗口。

### 边缘模式

- 从完整或极简模式进入时，保存当前来源模式和展开尺寸。
- 根据当前窗口矩形与当前显示器工作区计算最近的左、右或上边缘。
- 距离按窗口对应边到工作区边缘的绝对距离比较；距离相同时按左、右、上的固定优先级保持结果稳定。
- 将窗口收缩为现有边缘条尺寸并吸附到所选边缘，同时保留窗口在平行方向上的位置，并限制在工作区范围内。
- 已处于边缘模式时，不重新计算方向或改变几何信息，只显示并聚焦。

边缘模式的悬停展开和离开收起继续恢复其来源模式。右键选择完整或极简模式会结束边缘会话。

## 原地展示与边界校正

“原地展示”定义如下：

- 普通完整与极简模式之间切换时，优先保留当前窗口左上角。
- 若目标尺寸会超出当前显示器工作区，只移动超出边界的轴，使整个窗口保持可见。
- 从边缘模式展开时保持当前边缘接触，窗口向屏幕内部增长；平行于边缘的坐标保持不变并限制在工作区内。
- 切换模式和重新显示均不调用首次启动使用的右下角定位函数。

## 状态和事件

新增统一的托盘模式请求事件，载荷为 `full`、`compact` 或 `edge`。前端使用单一入口处理右键菜单请求，并复用同一完整模式转换逻辑处理双击。

转换期间设置现有过渡锁，避免悬停收起、窗口拖动和托盘请求并发修改状态。重复请求当前模式时只执行显示和聚焦。

## 错误处理

- 原生窗口尺寸或位置设置失败时，前端不提交新模式、不更新本地存储，并恢复边缘视觉状态。
- 托盘事件发送失败不退出程序，维持当前窗口状态。
- 无法取得当前显示器或工作区时，保留当前模式和位置，不执行部分转换。
- 显示和聚焦失败保持静默，与现有托盘行为一致。

## 测试

Rust 单元测试覆盖：

- 最近边缘选择，包括多显示器非零坐标和距离相同的稳定优先级。
- 普通模式尺寸变化后的工作区边界校正。
- 边缘模式从左、右、上方向展开时的锚定和边界限制。
- 单击延迟、双击取消单击以及第二次释放抑制逻辑。

前端回归测试覆盖：

- 托盘完整、极简和边缘请求的三类状态转换。
- 双击从边缘或极简进入完整模式，以及完整模式下不改变模式。
- 转换失败时不持久化错误状态。
- 后台刷新不会调用模式或窗口几何命令。

手动验证覆盖：

- 左键单击只原地隐藏或显示且不弹菜单。
- 左键双击在三种模式下符合预期且没有先隐藏再显示的闪烁。
- 右键菜单在窗口显示和隐藏时均可切换三种模式。
- 窗口靠近各显示器边界时切换模式不会越出工作区。
- 首次启动仍位于主显示器右下角。
