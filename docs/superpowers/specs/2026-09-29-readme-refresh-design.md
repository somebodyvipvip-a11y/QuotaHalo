# README 专业化更新设计

## 目标

将 QuotaHalo 的 README 更新为中文为主、适合公开 GitHub 仓库的项目主页，准确覆盖当前 `0.4.6` 分支已经实现的能力，并为普通用户、问题排查者和贡献者提供清晰入口。

## 信息结构

README 按以下顺序组织：

1. 项目名称、简短定位、平台／Release／许可证徽章和下载入口。
2. 真实运行截图及截图数据说明。
3. 核心功能，包括 Codex 额度、多服务积分、窗口缩放、积分项显隐、极简模式、边缘窥视、主题与透明度。
4. 快速开始，包括 Release 下载、系统要求和首次运行步骤。
5. 支持服务与连接方式，明确本机依赖和凭据保存位置。
6. 主要使用方式，包括完整模式、极简模式、边缘窥视、托盘和设置。
7. 数据刷新、隐私安全和已知限制。
8. 源码开发、构建、测试、贡献方式和许可证。

## 内容原则

- 只描述当前代码和现有设计文档能够确认的功能，不加入路线图式承诺。
- 使用简体中文，保留 Codex、WorkBuddy、TRAE、Qoder、WebView2 等产品和技术名称。
- 顶部徽章只使用稳定、可验证的仓库信息，不展示虚构的构建状态或下载量。
- 保留 `docs/images/quotahalo-main.png` 真实截图，不恢复已删除的概念图。
- 清楚区分“关闭到托盘”和“退出应用”，并解释百分比代表剩余额度。
- 边缘窥视说明限定为极简模式的左侧、右侧和顶部；不声称支持底部吸附。
- 凭据说明以当前实现为准：Codex 使用本机 CLI 会话，WorkBuddy 使用本机共享登录态，Qoder 和 TRAE 的凭据由 Windows 凭据管理器保存。
- 保留非官方关联声明，并提醒用户不要在 Issue 中提交 Token、Cookie 或个人信息。

## Git 与发布边界

- 当前 `src-tauri/src/main.rs` 和 `src/main.js` 的未提交修改属于用户已有的边缘窥视修复，README 更新不得覆盖或还原这些内容。
- README 完成后，运行前端启动检查、刷新生命周期检查、Rust 测试和 `git diff --check`。
- 根据当前功能与修复更新补丁版本，并将 README、现有修复及版本变更按目的提交。
- 将功能分支合并到 `main`，拉取并核对远端状态后推送到 GitHub。
- 本次请求只要求更新 README 和源码分支，不自动创建或替换 GitHub Release。

## 验收标准

- GitHub 仓库首页能在首屏看到项目用途、真实截图、下载入口和许可证。
- 新用户能够仅根据 README 完成下载、运行和服务连接。
- README 覆盖窗口缩放、积分显隐和边缘窥视等 `0.3.1` 之后的主要功能。
- 所有命令、文件路径、版本号和支持范围与仓库实际状态一致。
- 工作区原有修改被完整保留，测试通过，Git 历史清晰且远端 `main` 更新成功。
