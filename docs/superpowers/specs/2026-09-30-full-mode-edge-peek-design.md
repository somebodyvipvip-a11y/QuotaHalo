# 完整模式边缘窥视设计

## 目标

将现有仅支持极简模式的边缘窥视扩展到完整模式。用户拖动完整或极简窗口靠近当前显示器工作区的左侧、右侧或顶部时，窗口进入边缘窥视；悬停或拖动边缘条时恢复进入前的显示模式。程序启动时自动定位到屏幕右下角，以及程序主动调整窗口位置或尺寸时，不得因此自动进入边缘窥视。

## 交互规则

- 完整模式和极简模式均支持左侧、右侧和顶部吸附，继续忽略屏幕底部。
- 边缘判断沿用现有工作区、DPI 和 24 逻辑像素阈值规则。
- 边缘条沿用现有尺寸、主题进度条和交互样式，不因来源模式改变。
- 进入边缘窥视时记录来源模式：`full` 或 `compact`。
- 来源为完整模式时，同时记录收起前的实际窗口尺寸，以保留用户调整后的宽高。
- 悬停边缘条时立即展开：完整来源恢复完整内容及原尺寸，极简来源恢复 135×60 极简内容。
- 指针离开展开窗口后延迟收起，行为与现有极简模式一致。
- 按住边缘条拖动时，先按来源模式展开，再解除边缘状态并开始窗口拖动；拖动结束后可重新判断吸附。
- 用户主动切换完整/极简模式时清除已有边缘状态，避免来源模式和当前 UI 不一致。

## 激活控制

边缘检测仅由用户拖动窗口触发。前端在可拖动区域收到主键按下时，将本次移动标记为可触发边缘检测；窗口移动停止后执行一次吸附判断并清除标记。

以下程序性变化不设置该标记，因此不会触发边缘窥视：

- 首次启动时将完整窗口定位到屏幕右下角。
- 从托盘重新显示并重新定位窗口。
- 完整/极简模式切换引起的尺寸变化。
- 内容变化引起的完整窗口高度同步。
- 边缘窥视自身的收起和展开定位。

此规则不依赖固定延时，避免在启动较慢、不同 DPI 或不同设备上误判。

## 状态与接口

前端维护边缘会话状态：方向、是否已展开、是否正在切换、来源模式、展开尺寸及本次用户拖动是否已武装。现有边缘状态清理入口统一清除这些字段和计时器。

`snap_edge_peek` 在成功吸附时返回方向和收起前的物理窗口尺寸。前端保存该信息。`expand_edge_peek` 接收方向、来源模式和保存的尺寸：极简来源使用固定极简尺寸；完整来源恢复保存尺寸。进入边缘条时临时禁用窗口缩放，完整来源展开后恢复可缩放，极简来源保持不可缩放。

窗口位置继续由 Rust 使用当前显示器工作区计算，确保多显示器和 DPI 缩放行为与现有实现一致。若无法读取显示器、尺寸或位置，则保持当前正常模式，不进入边缘窥视。

## 范围

本次不改变以下行为：

- 启动时仍默认进入完整模式。
- 边缘窥视不支持屏幕底部。
- 边缘条仅显示 Codex 5 小时剩余额度，不增加网络请求。
- 完整模式和极简模式本身的内容、主题及刷新策略保持不变。

README 中将边缘窥视说明更新为同时支持完整与极简模式，并明确按来源模式展开。

## 验证

- Rust 单元测试覆盖完整/极简展开尺寸选择、原尺寸恢复、三个支持方向、底部不吸附及工作区边界。
- 前端生命周期测试覆盖两种来源模式、用户拖动武装、程序性移动不激活、悬停展开、离开收起和边缘条拖动。
- 手工验证首次启动位于右下角但保持完整模式；随后拖到右边缘可正常收起并展开回完整模式。
- 运行现有前端脚本、`cargo test`、构建检查和 `git diff --check`。

## 版本

该功能为向后兼容的新增能力，应用版本从 `0.4.7` 升至 `0.5.0`。实现提交同步更新 `package.json`、`package-lock.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock` 与 `src-tauri/tauri.conf.json`，保持版本一致。
