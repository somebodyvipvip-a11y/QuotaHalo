# QuotaHalo 超时状态保留设计

## 目标

当 Codex 额度读取因总时限超时而失败时，完整模式与极简模式都保留 Halo 圆环，不再切换到覆盖额度区的错误页面。

## 行为

- 每次成功获得 Codex 额度后，在前端内存保存最后一份成功快照。
- 新请求发起时保留最后有效 Halo 与百分比，并将状态文案改为“正在读取”；不把旧数据写成新数据。
- 仅当失败信息明确是读取超时时，使用最后成功快照继续渲染主 Halo、每周额度和重置时间，并将完整模式主文案改为“读取超时，请稍后重试”。极简模式使用能在 135px 窗口完整显示的短文案“读取超时”。
- 若本次进程生命周期内从未成功读到额度，超时时显示空轨道与破折号，不显示猜测百分比，文案仍为超时说明。
- 非超时的不可用状态继续显示现有错误页面，以区分认证、App Server 退出、响应格式错误和网络等异常。
- 刷新按钮、轮询频率、后端超时（单请求 15 秒、总计 50 秒）和额度读取接口均不改变。

## 实现边界

- 仅修改 `src/main.js`：保存最后成功快照；明确区分 loading、timeout 和其他 unavailable 渲染状态；使用现有 Halo 与额度渲染函数。
- 不新增依赖、持久化、后端命令或日志；不将额度数值写入本地存储。

## 验证

1. 成功读取后模拟超时：完整与极简模式均保留最后有效圆环，显示超时文案。
2. 首次读取即超时：两个模式显示空轨道、破折号和超时文案。
3. 非超时 unavailable：保留错误页面。
4. 后续成功读取：以新快照替换旧值和超时状态。
5. 运行 `node --check src/main.js`、`cargo check --manifest-path src-tauri/Cargo.toml` 和 `git diff --check`。
