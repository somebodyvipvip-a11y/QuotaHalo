# QuotaHalo 窗口与刷新可靠性设计

**状态：** 用户已审阅并批准；实现已完成，真实额度读取仍待用户桌面环境验证。

## 背景

QuotaHalo 目前通过 `cmd.exe` 打开 ChatGPT 用量页；无边框浮窗没有拖动绑定；每次刷新都会新建并终止一个 `codex app-server --stdio` 进程，额度读取最长可等待 150 秒；窗口虽然使用 CSS 圆角，但 Windows 原生透明窗口没有对应的圆角裁剪。用户报告黑色控制台窗口、无法拖动、刷新长时间旋转后出现 `-32603`，以及窗口显示方角。

## 目标

- 打开 ChatGPT 用量页时不显示控制台窗口。
- 允许从浮层的非交互区域拖动窗口，按钮仍保持点击功能。
- 复用 QuotaHalo 生命周期内的 Codex App Server stdio 会话，串行请求并缩短最长等待时间；失败时明确结束加载状态，不展示猜测或伪造的额度。
- 在 Windows 原生窗口区域实现与现有页面一致的圆角。
- 保持当前 Tauri 2、单文件裸 EXE 和本地 Codex 登录态，不接触、输出或保存认证令牌。

## 方案

Rust 侧以单个后台工作任务持有 Codex CLI App Server 子进程，完成一次 `initialize` 后通过消息通道串行处理刷新请求。每次刷新仍先读取账号状态，再调用 `account/rateLimits/read`；只保留当前既有的窗口解析和有效数据规则。每次刷新共用 15 秒总时限（包括必要的重连或重试）；App Server 退出或协议流失效时最多重启并重连一次，对 `-32603` 最多重试一次。任何超时、未登录或服务错误都返回现有不可用状态，不保留旧百分比冒充最新值。应用退出时关闭工作任务并终止其子进程。

前端继续以 `finally` 收尾刷新标志；刷新中按钮显示受限的加载状态，超时/失败后移除加载样式并呈现错误文本。现有自动刷新周期保持不变，避免同时扩大产品行为范围。

Windows 打开网址改用 `ShellExecuteW`，直接交给系统默认浏览器。浮层头部和空白内容区域注册 Tauri 拖动手势，明确排除刷新和用量页面按钮。CSS 仍负责面板的平滑边缘；Rust 在 Windows 窗口创建后取得 HWND 并设置与面板尺寸和 DPI 相符的 round-rect 窗口区域，使透明窗体外形被系统实际裁剪。窗口尺寸固定，圆角半径与 CSS 设计保持一致。

## 错误处理与隐私

服务启动失败、账号未登录、15 秒刷新总时限到期、服务内部错误和无目标额度窗口，都映射为有说明的不可用结果。每一条请求使用唯一递增的 JSON-RPC ID，并按 ID 匹配响应，避免串行会话下错误关联。不得把原始服务响应、账号标识或令牌写入日志。浏览器启动失败不影响浮层。

## 验证

- 单元测试覆盖 JSON-RPC 重试上限、请求/响应 ID 匹配、超时转换与额度解析回归。
- 前端回归检查确保成功、RPC 错误和超时三条路径都会结束加载状态。
- Windows release 构建后检查 GUI 子系统、无 `cmd.exe` 浏览器启动路径，并输出便携裸 EXE。
- 运行时验证用量链接直接打开浏览器、浮层可从内容区拖动且按钮可用、原生圆角与 CSS 面板边缘一致。
- 有登录的 Codex 环境下运行现有 live App Server 测试，确认刷新能取得真实窗口；本机 App Server 若再次返回服务端错误，界面必须有限时地停止加载并显示错误。

## 范围外

本次不改变额度字段和窗口识别规则，不增加 Qoder、Trae 或 WorkBuddy 数据源，不新增托盘/浮层布局，不修改自动刷新频率，也不尝试修复 Codex 服务本身的 `-32603` 内部错误；只保证复用会话、有限重试和明确失败反馈。
