# 托盘双击原地展开边缘模式设计

## 目标

修正托盘单击导致窗口重新定位到桌面右下角的行为，并新增托盘左键双击操作：当窗口处于边缘窥视时，在当前屏幕边缘原地退出边缘状态并切换为完整模式。

## 根因

Windows 托盘图标的一次左键操作会分别产生按下和松开事件，现有代码对两个事件都执行 `toggle_panel`，导致窗口连续隐藏和显示。显示路径又无条件调用 `position_panel`，最终把窗口重新放到主屏幕右下角。

双击序列还会包含第一次普通点击、双击事件和第二次松开。如果直接分别处理单击与双击，会出现先隐藏、闪烁或双击后再次执行单击的问题。

## 交互规则

### 单击

- 只处理左键松开，左键按下不执行窗口操作。
- 单击在系统双击判定时间结束后执行显示／隐藏。
- 显示窗口时保留上一次位置和当前显示模式，不重新定位。
- 软件首次启动仍由初始化流程定位到主屏幕右下角。

### 双击

- 收到左键双击时取消等待中的单击，并忽略该双击序列随后产生的第二次左键松开。
- 窗口处于边缘窥视时：确保窗口可见，在当前边缘原地展开为完整模式并获得焦点。
- 窗口不处于边缘窥视时：只确保窗口可见并获得焦点，不改变当前位置或当前完整／极简模式。

## 点击状态机

Rust 托盘层维护一个轻量状态：单击代次和“忽略下一次左键松开”标记。

- 第一次左键松开递增代次，并启动等待系统双击时间的异步任务。
- 等待结束时，仅当代次仍匹配才执行单击切换。
- 左键双击递增代次以取消等待任务，设置忽略下一次松开，并立即执行双击动作。
- 双击后的左键松开只清除忽略标记，不创建新的单击任务。

Windows 使用系统 `GetDoubleClickTime` 获取判定时间，尊重用户的双击速度设置。其他平台沿用安全的默认等待值；本应用发布目标仍为 Windows。

## 原地完整模式展开

Rust 新增边缘模式转完整模式命令，继续复用现有工作区、DPI、边缘方向和位置计算：

- 来源为完整模式时，恢复进入边缘前保存的物理宽高。
- 来源为极简模式时，使用 290×515 逻辑像素的默认完整尺寸，并按当前 DPI 转换。
- 左侧保持左对齐，右侧保持右对齐，顶部保持顶对齐；另一轴保留当前位置并限制在当前屏幕工作区内。
- 展开后恢复可缩放和圆角区域。

前端监听托盘双击动作：若存在边缘会话，则调用原地完整模式命令，成功后将 DOM 切换为完整模式、清除边缘状态并持久化 `full`；若不在边缘会话，则不改变模式。

## 显示与刷新

托盘显示路径不再调用 `position_panel`。它只执行取消最小化、显示、聚焦和请求后台刷新，因此不会破坏用户位置或边缘状态。首次启动的 `setup` 仍调用一次 `position_panel`。

边缘会话转为完整模式后，继续展示已有数据并正常后台刷新；不额外增加网络请求。

## 错误处理

- 原地展开命令获取显示器、DPI、位置或尺寸失败时保留原边缘状态，不清除前端会话。
- 托盘事件发送失败时不改变窗口模式；基础显示／聚焦仍可执行。
- 单击等待任务以代次校验取消，不保留不可回收的阻塞线程。

## 验证

- Rust 单元测试覆盖单击代次取消、双击后松开抑制、系统等待时间回退，以及完整／极简来源的目标尺寸。
- 前端生命周期测试覆盖托盘双击事件：完整来源恢复保存尺寸，极简来源使用默认完整尺寸，成功后清除边缘状态并持久化完整模式。
- 验证普通模式双击不改变完整／极简模式。
- 验证托盘单击隐藏和再次显示时保持当前位置，不调用右下角定位。
- 运行前端回归、Rust 测试、完整构建、版本一致性和 `git diff --check`。

## 版本

该改动新增托盘双击交互并调整单击语义，属于向后兼容的功能新增，版本从 `0.5.1` 升级为 `0.6.0`。
